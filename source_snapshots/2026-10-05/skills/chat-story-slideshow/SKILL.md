# Chat-story slideshow

Optional specialist. Use it only after the storyboard has already decided that a text thread is the natural artifact for that beat. It does not decide slide 1, the slide count, or the rest of the carousel.

If the strongest hook is a selfie, a lock screen, a photo, or any other artifact, do not use this skill.

## Does not impose
This skill never imposes a text opening, a bubble count, a fight, a checkout ending, or a payment ending on a concept that did not already need one.

## When a thread is the beat
Build the thread from the lines the storyboard already needs. There is no required bubble count. Use as many as the beat needs, and no lines whose only job is to fill the screen.

The offer name and the word discount stay out of the chat. A payment or order screen appears here only when the storyboard already made that screen the proof of a line. This skill does not add one.

## Construction
Dark-mode iMessage, or SMS green when the contact is not iMessage. Casual lowercase. Do not redraw bubbles. Build the thread deterministically from real bubble geometry. Do not ask an image model to draw the UI, the prices, or the totals.

If a screen is the proof slide, build that screen from a grounded reference. Amounts match. Do not place an order to capture it.

Pitch the thread before building it.
