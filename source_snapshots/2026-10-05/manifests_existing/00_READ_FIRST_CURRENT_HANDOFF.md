This is the Target visual/structural reference bank for staged creative production. It contains 26 original reference images from TARGET_REFERENCE_BANK_V1 plus one newer BYOMA order-details example, a manifest, and a Grok usage prompt.

Use the bank to select the correct Target commerce artifact for the story beat. Do **not** treat every image as a single universal template.

## Critical correction for the current workflow
A missing fresh live screenshot of the *exact* desired Target state is **not automatically a production blocker** when this bank already supports the information function and structure needed by the story.

Distinguish:

1. **Structural support** — do we have enough Target reference evidence to know what kind of surface/state carries the required information?
2. **Exact live-pixel capture** — do we have a current signed-in screenshot of that exact state and viewport?

For staged creative work, (1) is required. (2) is useful for fidelity calibration but should not send the creative pipeline back into an endless screenshot hunt unless the story needs a field/behavior the bank does not support.

This does **not** authorize inventing arbitrary Target semantics. Unsupported fields, statuses, attribution, Circle mechanics, or other app behavior must not be fabricated as factual Target behavior.

The Target artifact needs to prove only that the order contains birthday supplies plus the chore-cover item.
It does **not** need to prove who paid, who clicked the order button, or the sibling’s intent by itself.

### Remove-price test
If every price, discount, and total were blurred, Slide 2 must still advance the story through the item list alone.
